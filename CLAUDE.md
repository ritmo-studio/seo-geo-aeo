# seo-geo-aeo — правила работы

## Что это
Студийный инструмент «Ритма»: прогон сайта по чек-листу SEO / AEO / GEO.
Отдельный репозиторий, не часть библиотеки блоков (`seo-design-system`) — там
только блоки и вёрстка. Связи между репозиториями нет и не нужно: аудит работает
по живому сайту или по папке готовых `.html`, а не по исходникам библиотеки.

## Что держать неизменным
- **Только стандартная библиотека Python.** Инструмент должен копироваться одной
  папкой на любой сервер, где есть `python3`, и запускаться там без `pip install`.
  Зависимость — это причина не запуститься в тот день, когда она нужна.
- **Факты и эвристики разведены.** `sure=True` — то, что установлено по разметке,
  спорить не о чем. `sure=False` — догадка по признакам, в отчёте она идёт отдельным
  разделом «Нужен глаз». Смешивать нельзя: отчёт, где догадка лежит рядом с фактом,
  перестают читать на второй неделе.
- **Вежливость к серверу — не настройка, а условие работы.** Одна нить, пауза между
  запросами, `robots.txt`, ожидание `Retry-After`, выход после трёх отказов подряд,
  потолок запросов, lock-файл. Ослаблять это нельзя даже «на разок»: заблокированный
  бот не чинится кодом.
- **Скрипт не притворяется, что умеет больше.** Не рендерит JS, не меряет Core Web
  Vitals, не судит о качестве текста и не знает, по каким запросам страница должна
  находиться. Раздел «Чего здесь нет» в конце отчёта — часть продукта, а не оговорка.

## Охват важнее полноты

Полный обход большого сайта — не цель, а поломка: час сорок при паузе в секунду и
отчёт, который не читают. Дефекты сидят в шаблонах, поэтому прогон берёт выборку по
формам пути (`shape()` / `sample()` в `audit.py`), а `--crawl links` остаётся для
небольших сайтов и для проверки графа целиком.

Отсюда правило, которое нельзя размывать: **скрипт не делает выводов шире своего
охвата.** Граф пройден не целиком — проверка сирот молчит (`ctx.cover['full_graph']`),
непроверенные ссылки числятся непроверенными, а не битыми, и в «Коротко» стоит строка
охвата. Соблазн будет обратный: вернуть сирот, потому что «проверка же есть». Три
тысячи ложных сирот прячут ту одну настоящую — это не придирка, а потеря смысла
проверки.

Разметку страницы (`html`, `doc`) отпускаем сразу после её проверок — `Page.release()`.
Замер: 356 КБ на страницу против 14 КБ после. Новая проверка, которой нужен `html` на
уровне сайта, ломает это: такой проверке нужна выжимка в `Page`, а не разметка.

## Молчание — не факт

Отсутствие ответа никогда не превращается в вывод о содержимом. Страница, не
отдавшая 200, получает ровно одну находку «не загрузилась»: остальные проверки
её не трогают (`check_page` смотрит на `live`, исключение помечено `on_dead`).
Иначе каждый таймаут приносит дюжину мнимых находок — на 220boom.ru тринадцать
упавших страниц дали 195 замечаний из 499, и отчёт стал нечитаемым.

То же на уровне сайта: `status == 0` у robots.txt или sitemap.xml — это
`TECH-NO-ANSWER`, а не «нет файла». Ссылка без ответа считается непроверенной,
а не битой: по «битая ссылка → 0» пойдут править работающий раздел. Правило
общее — новая проверка, видя пустой ответ, молчит и не достраивает причину.

## Три инструмента, одна папка

Аудит, `pull-yandex.py` и GEO-трекер (отдельный репозиторий) не сливаются в один
скрипт и не будут. У них разный класс зависимостей (аудит — стандартная
библиотека без ключей; трекер — venv, платные ключи четырёх провайдеров, сервер
вне РФ), разный ритм (по требованию против раза в месяц) и разная цена ошибки
(повторный прогон аудита бесплатен, трекера — нет).

Связь только через данные и только в одну сторону: трекер и выгрузка кладут
`geo.json` и `yandex.json` в папку клиента, аудит их **читает, если они есть**.
Нет файлов — отчёт прежний, ни слова о соседях. Так аудит остаётся копируемым
папкой на любой сервер.

Чужие сводки в отчёт попадают дословно, разделом «Чужими глазами». Пересказывать
их своими словами нельзя: вся ценность сверки в том, что цифру посчитал другой
инструмент, а подмена формулировкой превращает её в наше же мнение. Сверки
(`cross`) идут отдельным абзацем «Коротко» по той же причине.

Аудит предсказывает, трекер измеряет: «нет Organization» и «в источниках 25 раз,
назван 8» — это прогноз и факт об одном и том же. Складывать их в одно число
бессмысленно, ставить рядом — единственное, ради чего связка нужна.

## Что отложено

**`geo.json` из трекера копируется руками.** Чтобы `tracker.py report --json-out`
писал сразу в папку аудита, трекеру нужно знать имя клиента на этой стороне: папка
аудита зовётся по хосту (`220boom-ru`, `ritmo-studio`), трекер — по слагу
(`ritmo`). Решение — поле вида `audit_slug: ritmo-studio` в
`clients/<slug>/config.yaml` и прокидывание его в `--json-out`. Отложено
сознательно: на одном клиенте соответствие пришлось бы угадывать, на двух станет
видно правило. Делать, когда появится второй клиент с обоими инструментами
(ожидался в ноябре 2026) — и тогда же убрать `cp` из README обоих репозиториев.

## Как добавлять проверку
1. Функция с `@page_check` (страница) или `@site_check` (сайт целиком) в `checks.py`,
   находки через `yield F(code, cat, sev, msg, fix, url, sure)`.
2. Строка в `TITLES` — название проверки человеком. По нему одинаковые находки
   схлопываются в один пункт отчёта, без него в отчёт попадёт сообщение случайной страницы.
3. Порог — в `LIM`, чтобы его переопределяли конфигом, а не спорили с кодом из-за
   одного сайта. Вес, если дефект дороже своего количества, — в `PRIO`.
4. Прогнать на живом сайте и на `--local`: проверка, которая падает на кривой
   разметке, хуже отсутствующей — кривая разметка и есть предмет аудита.

## Порядок работы
Коммиты мелкие и по одному смыслу, прямо в `main`: работа идёт в одиночку.
Пушит пользователь через GitHub Desktop, если не попросил иначе. Отчёты
(`reports/`) и кэш (`.audit-cache/`) в репозиторий не едут.
